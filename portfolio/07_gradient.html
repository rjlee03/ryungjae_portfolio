Project Gradient Noise

3D Graphics

Project Overview

This project implements 3D Improved Perlin Gradient Noise entirely on the GPU and uses it to generate a family of procedural texture patterns. A full-screen quad is rendered into an offscreen R32F framebuffer, where a fragment shader evaluates the noise function for every texel, producing a single 2D "slice" through a continuous 3D noise volume.

The generated noise texture can be viewed directly as a tiled 2D texture, or used to displace the vertices of a plane mesh to create a real-time, terrain-like 3D surface. A spectator camera lets you fly around the generated surface, and ImGui controls allow tuning the texture resolution, tiling scale, the noise pattern, and the Z-slice scrubbed through the 3D noise volume.

Tasks Completed

  • Texture Format Support: Extended the Texture class with a ColorFormat enum (RGBA8, RGBA32F, R32F) and a LoadAsFormat() method that allocates GPU storage with TexStorage2D on WebGL/OpenGL 4.2+ and falls back to TexImage2D on older desktop OpenGL.
  • Configurable FrameBuffer: Updated the FrameBuffer class so its ColorComponent enum maps directly onto the new Texture::ColorFormat values, added a non-const ColorTexture() accessor, and routed LoadWithSpecification() through LoadAsFormat() so any supported color format can be requested.
  • Improved 3D Perlin Noise (GLSL): Implemented gradient noise from scratch in gen_gradient_noise.frag using a hardcoded 64-entry permutation table, 12 fixed cube-edge gradient directions (cycled via the permutation table instead of randomly generated), and quintic fade/interpolation - no gradient derivatives required.
  • Noise Patterns: Built Plain Gradient, Fractal Sum, Turbulence, Marble, and Wood patterns on top of the base noise function, each remapped from its native range into [0,1] for storage in the R32F noise texture.
  • Seamless Tiling: Designed the noise lattice so that texture coordinates [0,1] map to exactly one period of the noise (and each fractal octave wraps at its own period), so the generated texture tiles seamlessly under GL_REPEAT when the tiling scale is increased.
  • Visualization Shaders: Wrote simple.vert/simple.frag to display a 2D slice of the noise as a tiled textured quad, and surface.vert (reusing simple.frag) to displace a high-resolution plane mesh by the noise texture, producing a 3D terrain visualization.
  • Demo Integration: Registered the demo in the DemosFactory, added an offscreen rendering pass each frame, and exposed ImGui controls for texture resolution, tiling scale, Z-slice, view mode (texture vs. surface), pattern type, and surface mesh resolution/scale.
  • Technologies Used: C++20, OpenGL 4.x/ES3 (GLSL ES 3.00), GLM, ImGui, CMake for cross-platform builds (Windows x64 + WebGL/Emscripten).

Reflection

Challenges Faced: The trickiest part was making the noise function periodic without simply relying on the permutation table's natural 64-element wraparound, since that frequency was far too high for a visually pleasing texture. I also had to be careful with the classic Perlin lattice-hashing trick (using perm[A]+1 to represent neighboring lattice cells), which breaks once you introduce a custom, smaller wrap period.

Solutions Implemented: Instead of the classic "+1" hashing shortcut, I explicitly compute both the current and next lattice coordinate for each axis with mod(coord, period) before hashing, which guarantees noise(0) == noise(period) in every dimension. For fractal sum and turbulence, each octave doubles both the sampling frequency and the wrap period together, so every octave remains independently tileable. Sampling the noise texture in the vertex shader for the surface displacement required switching from texture() to textureLod(), since implicit derivatives aren't available outside fragment shaders.

Key Learnings: This project gave me a much deeper understanding of how Improved Perlin Noise actually works under the hood - the role of the permutation table, why 12 gradient directions are used instead of fully random ones, and why quintic fading matters for smooth derivatives. I also learned how useful it is to generate procedural data into an offscreen framebuffer once per frame and reuse it for multiple visualizations (a flat textured quad and a displaced 3D surface) rather than recomputing the noise per-vertex or per-pixel in the final pass.
